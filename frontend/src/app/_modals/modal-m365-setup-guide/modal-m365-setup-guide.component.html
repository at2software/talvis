Microsoft 365 setup guide

You need the Entra role Global Administrator (or Cloud Application Administrator plus Exchange Administrator), Teams admin rights and, for Teams only, an Azure subscription — pay-as-you-go is enough, the F0 bot tier is free. One app registration serves automatic replies, the TALVIS calendar, the TALVIS address book and Teams.

  1. Register the app
    Entra admin center → App registrations → New registration. Name it TALVIS, choose "Accounts in this organizational directory only" (single tenant) and leave the redirect URI empty. Copy the Directory (tenant) ID and the Application (client) ID from the overview page into "tenant id" and "client id" of this connector. open Entra admin centeropen_in_new
  2. Grant Graph permissions
    API permissions → Add a permission → Microsoft Graph → Application permissions:
    @for (permission of permissions; track permission.name) { }
    {{ permission.name }} {{ permission.purpose }}
    Then click "Grant admin consent" — every row must show a green check mark. Mailbox settings, calendars and contacts are deliberately not granted here; step 4 restricts them to a group.
  3. Create a client secret
    Certificates & secrets → New client secret, expiry 24 months. Copy the Value — not the Secret ID, and it is shown only once — into "client secret" and enter its expiry date into "secret expires at". Once the secret expires, the integration stops until a new one is saved.
  4. Restrict mailbox access to a group
    Automatic replies, the TALVIS calendar and the TALVIS address book use Exchange Online RBAC for Applications, limited to the members of one group. Create a mail-enabled security group in the Exchange admin center and add everyone whose mailbox TALVIS should write to. The three role assignments grant MailboxSettings for the automatic reply, Calendars for the TALVIS calendar and Contacts for the TALVIS address book.
    The object id is under Entra → Enterprise applications → TALVIS → Object ID. It differs from the object id of the app registration.
    Run in PowerShell — install the module once with Install-Module ExchangeOnlineManagement

    The last command must report InScope = True for a group member. It can take up to 2 hours until the assignment takes effect. New colleagues later only need to be added to the group.
  5. Connect Microsoft Teams (optional)
    Azure portal → Create a resource → Azure Bot: pricing tier F0, type single tenant, creation type "Use existing app registration" with the client id from step 1. Under Channels, add Microsoft Teams with the default settings. Under Configuration, set the messaging endpoint to: open Azure portalopen_in_new
    {{ messagingEndpoint }}
    If TALVIS runs behind a login proxy, this endpoint must be reachable without it — TALVIS verifies the Bot Framework token itself.
    In Teams, create or pick the team for the project channels and copy its id — the groupId value from "Get link to team" — into "team id". Optionally enter a channel id for company-wide announcements into "town square". A team holds at most 1000 channels; TALVIS archives channels of completed projects instead of deleting them.
  6. Install the Teams app
    Save this connector first, then download the app package. Upload it in the Teams admin center → Teams apps → Manage apps → Upload and add the app to the team — without that, the bot cannot post there. To let the bot send direct messages, pre-install the app for the users via a setup policy. open Teams admin centeropen_in_new
  7. Connect and enable per person
    Each person connects their own Microsoft 365 account in their profile (vCard page → "Connect Microsoft 365") by signing in with Microsoft, then switches on the features they want: automatic reply, TALVIS calendar and TALVIS address book. Admins can disconnect an account in HR → contact.
